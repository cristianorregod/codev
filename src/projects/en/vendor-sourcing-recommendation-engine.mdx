## My role

The project started as an improvement to an existing quoting bot: I studied how it worked and proposed an initiative to improve it with multiple search levels and multiple sources. As the sole author, I took it from design to implementation: data extraction, modeling, search, recommendations, evaluation and the API service.

- **Incremental extraction**: Built the ERP extraction with watermarks and hash-based upserts into raw tables.
- **Transformation layer**: Designed the SQL layer that builds a consolidated core model and a vendor×brand performance score from historical activity.
- **Canonicalization**: Normalized items and brands so the same product can be found under different spellings.
- **Search and recommendations**: Developed the multi-step item search and the vendor recommendation logic.
- **Evaluation**: Wrote offline evaluation and backtesting commands to measure quality before any rollout.
- **API service**: Built a containerized FastAPI service with API-key authentication and request logging.

## Key project features

- Multi-step item search: internal code → exact part number → fuzzy part number with trigram similarity → full-text.
- Vendor recommendations (primary and backups) with confidence and human-readable reasons.
- Daily scheduled refresh of the whole pipeline.
- Offline evaluation and backtesting commands.
- Currently deterministic (no ML or embeddings) and designed as the data foundation for a future AI sourcing agent, with embeddings and RAG planned.

## Impact achieved

The engine cuts the time sales users spend on sourcing, that is, finding vendors for the items they are asked for. It searches internal sources (purchase history), the vendor catalog through RAG and the internet, and suggests 3 scored vendors per item. That reduces their operational time by about 70%, depending on the number of items.

In an offline evaluation on a test environment, the engine reached:

- Item search hit@1: 99.8% with brand + part number, 98.2% with part number only and 96.4% with a one-character typo.
- Recommendation backtest hit@1: 88.5% for previously purchased items.
- Search p50 latency of about 200 ms, over roughly 490k processed rows.
