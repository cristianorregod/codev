## Mi rol

La iniciativa de construir este servidor fue mía y sigo siendo su responsable directo. Diseñé la arquitectura y construí la base en solitario durante los primeros meses; después se sumó el equipo de BI, al que le enseñé a crear nuevas herramientas siguiendo la arquitectura del proyecto. Desde entonces ese equipo desarrolla herramientas de analítica y yo me encargo de la revisión de código y de los despliegues.

- **Servidor base y transporte**: Desarrollé el servidor MCP con transporte Streamable HTTP y su configuración en Docker.
- **Autenticación**: Integré OAuth con Microsoft Entra ID para que cada llamada quede atribuida al usuario autenticado.
- **Herramientas por dominio**: Desarrollé la mayoría de las herramientas de ventas y operaciones, además de las de notificaciones.
- **Analítica de uso**: Construí herramientas para medir la adopción y el uso del propio servidor.
- **Documentación de arquitectura**: Documenté el diseño por capas y las convenciones para agregar nuevas herramientas.

## Funcionalidades clave del proyecto

- 25 herramientas en 7 dominios: ventas, operaciones, finanzas, analítica de conversaciones con clientes, desempeño, archivos/datasets y notificaciones.
- 23 herramientas son de solo lectura y están anotadas como tales; 2 herramientas de acción envían correos y mensajes de Teams mediante automatización de flujos.
- Middleware que audita cada llamada (herramienta, usuario, duración, resultado) en PostgreSQL, con ocultamiento de datos sensibles.
- SQL parametrizado, validación de entradas y un formato de respuesta común para todas las herramientas.
- Diseño limpio por capas en cada funcionalidad: herramientas → casos de uso → consultas → dominio.
- Fuentes de datos: el ERP (vía JDBC) y PostgreSQL, con pruebas automatizadas.

## Impacto logrado

Los usuarios ya no dependen de abrir un ticket para obtener un reporte o construir una gráfica: cada persona arma sus propias métricas conversando con un asistente como Claude o ChatGPT. Esto redujo los tickets repetitivos de distintas áreas y promovió la autonomía de los usuarios: una métrica que como ticket para una gráfica en Tableau podía tardar hasta una semana ahora se obtiene en minutos, y cada acceso sigue siendo trazable a un usuario concreto.

## Tecnologías

| Tecnología         | Uso / Implementación                                                        |
| ------------------ | --------------------------------------------------------------------------- |
| Python             | Lenguaje principal del servidor, los casos de uso y las consultas de datos. |
| FastMCP            | Framework para exponer las herramientas mediante Model Context Protocol.    |
| PostgreSQL         | Fuente de datos analíticos y registro de auditoría de cada llamada.         |
| Docker             | Contenerización del servidor para despliegues consistentes.                 |
| Microsoft Entra ID | Autenticación OAuth y atribución por usuario de cada llamada.               |
| JDBC               | Acceso de lectura a los datos del ERP.                                      |
