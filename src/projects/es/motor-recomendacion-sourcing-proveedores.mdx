## Mi rol

El proyecto nació como una mejora a un bot de cotización existente: estudié cómo funcionaba y propuse una iniciativa para mejorarlo con varios niveles de búsqueda y múltiples fuentes. Como único autor, lo llevé desde el diseño hasta la implementación: extracción de datos, modelado, búsqueda, recomendaciones, evaluación y el servicio API.

- **Extracción incremental**: Desarrollé la extracción desde el ERP con marcas de agua (watermarks) y upserts basados en hash hacia tablas raw.
- **Capa de transformación**: Diseñé la capa SQL que construye un modelo core consolidado y un puntaje de desempeño proveedor×marca a partir de la actividad histórica.
- **Canonicalización**: Normalicé ítems y marcas para que un mismo producto pueda encontrarse con distintas escrituras.
- **Búsqueda y recomendaciones**: Desarrollé la búsqueda de ítems en varios pasos y la lógica de recomendación de proveedores.
- **Evaluación**: Creé comandos de evaluación offline y backtesting para medir la calidad antes de cualquier despliegue.
- **Servicio API**: Construí un servicio FastAPI contenerizado con autenticación por API key y registro de solicitudes.

## Funcionalidades clave del proyecto

- Búsqueda de ítems en varios pasos: código interno → número de parte exacto → número de parte aproximado por similitud de trigramas → texto completo.
- Recomendaciones de proveedores (principal y alternativos) con nivel de confianza y razones legibles.
- Actualización diaria programada de todo el pipeline.
- Comandos de evaluación offline y backtesting.
- Actualmente determinístico (sin ML ni embeddings) y diseñado como base de datos para un futuro agente de sourcing con IA, con embeddings y RAG planificados.

## Impacto logrado

El motor reduce el tiempo que los usuarios de ventas dedican al sourcing, es decir, a encontrar proveedores para los ítems que les solicitan. Busca en fuentes internas (el historial), en el catálogo de proveedores mediante RAG y en internet, y sugiere 3 proveedores con puntaje para cada ítem. Así, su tiempo operativo se reduce cerca de un 70%, según la cantidad de ítems.

En una evaluación offline sobre un entorno de pruebas, el motor alcanzó:

- Búsqueda de ítems hit@1: 99.8% con marca + número de parte, 98.2% solo con número de parte y 96.4% con un error de un carácter.
- Backtest de recomendaciones hit@1: 88.5% para ítems comprados previamente.
- Latencia p50 de búsqueda de unos 200 ms, sobre aproximadamente 490k filas procesadas.
